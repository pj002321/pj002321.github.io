일하는 방식

결과를 보기 전에 기준을 정하고, 만든 모델이 아닌 다른 모델로 검증합니다. AI 코딩 도구도 같은 원칙으로 규칙과 게이트를 걸어 씁니다.

기준 먼저
Metric 설계		측정 전에 주지표와 판정 규칙을 정하고, 품질 지표와 '0이어야 하는' 안전 지표를 나눕니다MRR 주지표, 구간이 겹치면 동률 / 알레르기 위반은 0건이어야 함
평가셋 구축
Golden Set · Holdout		정답을 아는 골든셋을 만들고 골든셋 자체도 먼저 검증합니다. 악조건은 별도 셋으로 분리합니다홀드아웃 275건, 질문 22문항 (자가검증 0 / 22), 악조건 5종
같은 조건 측정
재현 가능한 Benchmark		서비스와 똑같은 필터 · 조건으로 재고, 날짜 · 표본 수 · 모델 · 신뢰구간을 함께 기록합니다평가 스크립트의 축종 필터 누락을 찾아 수정 (18.2 → 21.2%)
통계로 비교
Bootstrap 신뢰구간		차이가 신뢰구간 안이면 개선이 아니라 운으로 봅니다. 모델 비교는 같은 표본으로 짝지어 봅니다임베딩 3종 부트스트랩 4,000회 → 동률, 9.5배 빠른 모델 채택
채택 · 기각 기록
실험 로그		효과가 없거나 나빠진 결과도 지우지 않고 이유와 함께 남깁니다인덱스 24 → 53ms 미채택, OpenAI 전환 시 hit@5 하락 기록
테스트로 고정
Regression Test		고친 버그는 회귀 테스트로, LLM 답변은 다른 모델의 교차 검증으로, 작업 완료는 '어떻게 확인했나'로 확인합니다태풍 라우팅 회귀 테스트, 할루시네이션 검증 오탐 제거 후 정확도 0.9 ~ 1.0

01

규칙

AI에게 부탁하지 않고, 지켜야 할 선을 먼저 긋습니다

쓰는 방법남기는 결과물
저장소마다 AI의 작업 범위 · 실행 방법 · 금지 규칙을 문서로 먼저 둡니다. 예: AI 서버를 공개 주소로 열지 않기, 로그인 확인은 서버 검증 함수로만 하기저장소별 AI 작업 규칙 문서 (AGENTS.md · CLAUDE.md)
규칙을 문서에서 강제 장치로 옮겼습니다. 테스트가 통과하기 전에는 AI가 작업을 끝내지 못하는 완료 게이트, 수정 금지 경로 차단, 만드는 에이전트와 채점하는 에이전트 분리를 마법사로 설치합니다harness-kit (직접 제작) · 실세션 검증: 테스트를 깨고 끝내려 하자 2회 차단, 게이트를 끄라는 지시는 권한 거부
02

위임

큰 작업은 나누고, 화면은 도구로 점검합니다

쓰는 방법남기는 결과물
계획 담당 에이전트로 단계를 나눈 뒤, 조사 · 구현 · 리뷰를 여러 하위 에이전트에 동시에 맡기고 결과를 합쳐 판단합니다기능 1개 = 커밋 1개, 커밋에 AI 공동 작성 표기
Impeccable 디자인 스킬로 AI가 만든 화면에 흔한 패턴(과한 바운스, 사이드 탭 등)을 탐지합니다. 브랜드상 의도한 것은 사유를 남기고 예외 처리하고, 랜딩은 첫 화면 구성을 여러 시안으로 비교해 고릅니다탐지 예외 기록 (오늘뭐멍냥), 랜딩 시안 비교 기록 (LIFE,FIT)

04

자동화

프로젝트마다 같은 원칙으로 반복 작업을 없앱니다

원칙하는 방법프로젝트 예시
세 번 손으로 하면 메뉴로가상환경 생성 → 패키지 설치 → 환경 검증을 VS Code 작업 메뉴 하나로 끝냅니다. 팀원도 명령을 외울 필요가 없습니다Safe-Farm 13개 · 오늘뭐멍냥 19개 작업 메뉴 (팀 저장소)
순서가 있으면 번호를여러 단계 데이터 작업은 번호 순서대로 누르면 끝나고, 중간 단계부터 다시 돌릴 수도 있게 나눕니다YOLO: Gazebo 캡처 → 분할 · Kaggle 업로드 → 학습 → 모델 받기 (9단계)
RAG: 적재 → 조각 → 색인 → 평가
검사는 무료 · 유료를 나눠서기본 실행은 요금이 안 드는 검사만 돌리고 LLM 채점은 옵션으로 분리합니다. 검색이 통과해야 LLM을 재도록 순서를 고정합니다python -m eval all [--with-llm] · 품질 검사 4종 (오늘뭐멍냥)
AI 작업은 게이트로사람이 매번 "테스트 돌렸어?"라고 묻지 않도록, 끝내기 전에 검사를 자동으로 돌리고 실패하면 막습니다harness-kit 완료 게이트
